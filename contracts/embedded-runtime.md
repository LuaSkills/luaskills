# 嵌入式插件运行时契约

状态：面向 0.6.0 的开发接口，实际包版本仍以 `Cargo.toml` 为准。正式调用、固定会话、插件聚合预算、实际模块池、实例能力队列、Lua 绑定及版本一 JSON FFI 已接通；三个 SDK 的异步驱动、回调泵、关闭作用域与兼容性校验已在各自开发仓库实现并取得本地真实消费证据。有界磁盘阶段检查点、可信执行代次绑定、宿主分发意图预写、已返回副作用证据确认、历史对账及显式存储／写入线程恢复已提供核心与跨语言入口，具体证据及限制见下文和 FFI 契约。Rust 另提供随真实池寿命保留的原生资源所有者。自动预热、完整更新事务、Vulcan 正式运行时接入及正式发布验收仍待完成。此开发状态不代表已经发布，也不代替跨平台与长期稳定性验收。

## 权威与实现入口

- Rust 类型：`src/runtime/embedded/`。
- 实际 VM：`src/runtime/engine/lease/embedded.rs`；精确宿主包解析在其 `paths` 子模块，依赖、对象身份及逻辑目录校验复用既有基础实现。
- 现有 System 执行边界：[system-lease-execution.md](system-lease-execution.md)。
- 版本化传输与命令：[embedded-ffi.md](embedded-ffi.md)；SDK 实现及语言生命周期以各 SDK 仓库源码和测试为准，核心文档不另行复制其状态机。
- 本契约与 Rust 类型、生成 Schema、SDK 同批变更；不能把文档转录当作独立协议权威。

## 当前类型化模块

`ModuleDefinition` 冻结插件身份、包代次、安全分区、包根、依赖清单、工作区、逻辑目录、挂载元数据、源码及导出声明。定义来自可信宿主，不接受 Lua 参数覆盖身份。每项 `ModuleExport` 必须声明精确名称、输入和输出 Schema。

`LuaEngine::create_embedded_module` 在分配 VM 前编译值契约，然后解析宿主显式授权的精确绝对包根、依赖清单及逻辑目录，执行一次模块源码并捕获导出函数。包根不要求位于旧 `system_lua_lib` 内，也不会复制或重定位包；旧 System 租约继续要求其信任根的严格子目录。模块不注册到旧租约管理器，因此不消耗其固定租约槽位。该低层入口本身不代替资源治理器，最终高级运行时必须在调用前取得资源令牌。

此声明只能由可信原生宿主提供，FFI／SDK 调用方承担同一责任。宿主必须先核验包来源、内容代次、权限及目录所有权；不能让插件清单或业务参数直接选择路径。依赖清单必须为包内相对文件，规范化后不能逃出精确包根；cwd 只能在该包或显式授权工作区内。包、清单、工作区及 cwd 的原生文件对象身份在创建时固定，后续实际执行前重新校验。宿主仍需用真实资源所有者保留不可变文件并限制外部写入；路径身份检查不是文件系统沙箱，也不能保证不可信并发写入者下的内容不可变。

受管包类型为 `embedded_plugin`，与相同路径的 `system_plugin` 使用不同 Worker 身份。现有受保护的 `vulcan.runtime.system_plugin` 及 Worker 的同名上下文槽继续承载实例元数据，名称沿用不表示 System 路径授权。模块沿用已配置的基础 Lua／受管运行时能力；精确包路径授权不自动限制任意 Lua 文件、进程或原生访问。第三方插件宿主仍须封装受限执行环境并通过显式能力注册暴露权限，不能把本接口宣称为完整插件沙箱。

源码必须返回函数表。导出函数捕获后，插件修改返回表的字段不会重定向宿主已经验证的函数身份。每次调用通过 `Function::call` 传递结构化参数并返回结构化值，不拼接新的代码包装，不返回嵌套编码的 JSON 文本。

`ModuleInvocation` 使用宿主上下文与同一个 `CallControl`。调用重新验证包和目录对象身份。参数 Schema 在业务代码执行前校验；结果 Schema 在请求所属资源事务提交前校验。参数不合法不会执行插件；执行或清理失败的实例禁止继续复用。

模块持有引擎强引用至全部 Lua 句柄析构后，避免 Lua 终结器访问已经卸载的动态库。关闭先退役受管包资源；清理失败不能报告可安全释放容量。

嵌入式 VM 在加载插件源码前显式关闭 LuaJIT 编译引擎并清空跟踪缓存，使解释执行接受指令预算钩子。只关闭初始化包装函数的 JIT 不能约束后续导出函数；引擎模式与函数模式的区别见 [LuaJIT 官方 C API 说明](https://luajit.org/ext_c_api.html)。此约束覆盖初始化、业务调用及下述显式关闭调用。它仍是协作式执行预算：可信宿主必须禁止插件重新配置 JIT／调试钩子，不可中断的原生代码和终结器不受 Lua 指令钩子强制中断，进程内接口不能充当恶意代码的隔离沙箱。

## JSON 值契约

新协议固定使用 JSON Schema Draft 2020-12。存在 `$schema` 时必须与 `EMBEDDED_SCHEMA_DIALECT` 一致。支持内嵌 `$defs` 及内部引用；外部 HTTP、文件或其他资源引用直接拒绝，不能在编译契约时下载资源或读取任意文件。

依赖精确使用与当前消费宿主相同的 `jsonschema = 0.49.9`，关闭默认网络和文件解析功能，并安装拒绝外部检索的解析器。即使消费程序通过 Cargo 功能合并启用其他检索功能，也不能改变本契约的离线行为。

正则模式使用该库提供的线性时间正则引擎；需要回溯、反向引用或前后查找的模式在契约编译时明确失败。`format` 使用所选方言的默认注解语义，不自行承诺额外格式断言。未来扩大支持范围时，必须同步描述、测试和 SDK 能力信息。

校验错误报告路径，不打印被拒绝的值。JSON 空值、空对象、空数组、Unicode 和嵌入零字节按规范 serde 映射往返。操作记录中保留的单个应用值受运行时配置的序列化大小约束；固定协议错误元数据单独记账，不能回显超大值。当前低层直接模块调用尚未接入统一输入、输出字节限制，不能将操作记录上限理解为 Lua 内存硬上限。

Rust 宿主可复用公开 `runtime::embedded::json_size(value, limit)` 在生成业务信封前检查序列化字节数。
该接口使用核心同一流式计数器，包含 UTF-8 和 JSON 转义；超过限制返回 `CapacityExceeded`，
序列化失败返回 `InvalidArgument`，不为计数分配完整 JSON 副本。它不预留调度容量，也不替代
实际调用入场校验；对自定义 `Serialize` 实现，宿主仍须保证后续序列化与预检期间的数据一致。

## 资源治理基础

`EmbeddedRuntimeConfig` 所有预算显式传入，宿主负责解析默认值，SDK 不能重新定义一份默认配置。`PluginPoolConfig` 将容量归属、复用、串行要求与执行后端分开声明；当前声明工作进程后端会明确返回不支持。

`PoolGovernor` 只保存资源元数据，不在锁内执行 Lua、宿主回调或 VM 析构。公共分组没有专用预留。专用分组的未使用最小容量不出借。注册与分配同时核对父级和分组预算，不允许先占一层许可再等待另一层。

`VmReservation` 从创建前持续存在至实际销毁后；创建、空闲、运行及退役均计入常驻账本。执行许可通过独占借用绑定到常驻预留，阻止运行期间释放槽位。等待宿主结果期间仍占执行许可；固定会话空闲时仅占常驻容量。

此治理器只负责精确预算。注册池数量同样有显式上限，正在排空的旧代次仍占注册和预留容量；不会通过创建大量零常驻池绕过元数据容量约束。

## 实际模块池与退役

`EmbeddedPoolManager` 共享父级治理器、不可变引擎和一个后台清理线程。`ModulePool` 绑定完整 `ModuleDefinition`，因此代码代次、包路径、安全分区、工作区、挂载及导出不随调用参数变化。不同池共享容量，不共享 Lua 状态。低层分组对应一个完整执行域；正式 `EmbeddedRuntime` 在其上执行跨域插件聚合限制。独立使用低层模块或其他池管理器不属于同一个正式插件预算，不能把本预算宣称为整个进程的总资源上限。

`ModuleLease` 独占真实实例，Rust 借用规则要求同一实例顺序调用。普通复用池归还成功且未达到使用次数上限的实例；单次池禁止同一租借第二次调用，归还后退役。会话池只允许显式 `open_session`，会话实例保持固定，释放时退役而非转入普通空闲池。空闲会话占常驻名额，不占执行许可。

分配与执行源码初始化分开：池先持有 VM 和容量，再执行初始化。初始化失败或 panic 后，实例仍交给后台退役。初始化契约只能消费一次，不能在部分副作用发生后重试同一个实例。实际调用期间不持有池元数据锁或宿主技能管理器全局锁；两个真实 VM 在同一引擎内同时等待宿主回调的行为已在本机验证。

低层 `prewarm` 显式准备指定数量实例，保留全部借用直至数量满足，避免用同一个实例重复计数。低层 `retire_expired` 回收过期空闲实例，保留专用池的最小空闲数量；重复回收不能把正在退役的实例误算为可驱逐的最小保障。低层池单独使用时仍需宿主调度维护。自动预热尚未接入，不能把专用容量预留误解为已执行源码初始化。

正式 `EmbeddedRuntime` 的可复用实例由调度器独占保留，物理 `ModulePool` 只负责构造、执行许可和真实资源退役，不同时保存第二份空闲缓存。业务结束后，原操作继续持有精确租借直到结果封存、磁盘确认及终态发布；存储失败或待确认期间不能提前复用，也不能按空闲期限驱逐。正式调用仍使用原 `Reusable` 策略和空会话身份，不伪造固定会话。调度器从终态发布后开始计算空闲期限，跨池容量压力与过期回收均只选择已确认空闲实例，并保留专用最小空闲数量。失败、使用额度耗尽、池代次关闭及运行时关闭永久排除再次复用。

正式缓存退役在调度锁外交给物理清理服务；在真实退役回执完成前仍保留缓存元数据及实际容量。遗忘池会同步核对已完成回执，不需要等待下一次维护扫描，但不能跳过未完成所有权。带关闭声明的可复用实例先经过独立业务关闭及持久确认，随后才物理退役；缓存驱逐不得在资源析构或其重试中调用插件导出。

退役从真实资源关闭、Lua VM 析构到容量令牌释放均保持所有权。一个后台线程轮转重试失败资源，不按失败数量增长线程。专用注册由每个常驻实例共同保留；已请求关闭的池在最后一个实例销毁后释放注册和最小预留，不要求调用方先丢弃旧池句柄。旧句柄的释放标记与资源查询使用同一身份锁，不能查询或注销新注册的同名池。进程内原生清理可能阻塞；当前不承诺清理任务的硬时限或原生崩溃隔离。

受管子进程服务已补充清理中记录：从活动表摘除不等于已经销毁，并发退役和新容量入场仍能看到该记录。userdata 清理回调被取走不等于执行完成；语言专属清理结束后才注销。测试在精确同步点阻塞回调，验证并发退役不能报告假完成。

`request_close` 关闭全部池的新入场并调度空闲退役；已借出实例与固定会话继续保留归属。`poll_closed` 只有在常驻数归零且后台清理线程已经等待退出后才返回真。取消请求、池关闭请求、实例清理完成和线程退出不能互相替代。FFI 与 SDK 关闭使用此完整关闭证据，并另外等待各语言实际调用线程及回调退出；仅丢弃 Rust 所有者不等于可以马上卸载所在动态库。

低层池接口同步取得许可，容量不足直接报错；`serial` 约束同时运行数量。正式运行时在其上提供有界公平队列及域内先进先出分发。低层池调用不会自动进入正式队列，不能把低层或本机调度测试当成 SDK 或发布验收。

### 显式同实例关闭原语

Rust 低层 `ModuleLease::finalize(ModuleInvocation)` 在已成功初始化的同一 VM 中至多尝试一次指定的声明导出。导出名称、结构化参数、可信上下文与独立有限 `CallControl` 由原生宿主提供。业务结果仍由调用方保留，返回值只表示关闭函数结果；关闭成功不表示资源已经退役。调用方随后仍须执行 `finish` 或 `close` 并观察真实退役回执。

业务报错、取消、超时、单次调用限制、使用次数耗尽及池代次关闭不阻止仍被持有的已初始化 VM 尝试关闭。未完成初始化、已经实际关闭或已经认领关闭尝试的模块直接拒绝，不能重新执行初始化源码。关闭仍使用冻结模块身份、原输入／输出契约、目录对象校验及实时权限；关闭不会恢复已撤销能力，也不会生成更高权限身份。

关闭先取得原治理器的实际执行许可，持有 VM 和资源所有权直到真实返回。容量拒绝发生于尝试前，没有执行用户函数，允许宿主显式重试；这不构成已进入关闭阶段。许可取得后，在参数校验和用户代码前记录已尝试，随后即使未声明导出、非法参数、取消、超时、错误或异常展开，也不允许再次关闭。实例永久退出业务复用；成功关闭也不能回到空闲池。原生回调阻塞时，取消和池关闭均不能提前释放该执行许可或常驻容量。

`Drop`、`close` 和后台受管资源退役重试不调用该业务关闭导出，因此不会因资源清理重试重放插件副作用。低层调用方自行保留业务与关闭结果，并使用已有操作证据机制明确记录副作用；单独调用此方法不提供跨重启的至多一次保证。

### 正式单次调用的自动关闭阶段

可信宿主可在 `ModuleDefinition.finalizer` 声明已导出的函数、固定 JSON 参数及独立有限 `timeout_ms`。注册时校验导出存在、输入 Schema、预算和声明字节数，声明省略时保持既有行为。当前正式调度器接受 `SingleCall`、`Session` 和 `Reusable`。宿主生产路由的迁移状态以宿主仓库契约为准。以下两阶段同操作规则适用于单次调用；固定会话及可复用实例使用下文说明的独立关闭操作。

业务返回后保留原 VM、请求上下文和操作入场，等待业务宿主处理器全部真实结束，冻结业务结果并进入 `Cleaning`。磁盘模式先确认关闭意图，再由原固定执行器至多执行一次关闭函数；清理预算从此次签发开始，原业务取消或截止时间不续期、不覆盖该独立预算。关闭返回后再持久确认关闭结果，最后才退役 VM 并发布终态。关闭错误、超时或存储失败不能重放函数；存储故障继续持有 VM，只接受既有显式恢复与检查点重试。确认丢失只重试相同候选。崩溃后没有原执行所有者时，不得据未出现关闭结果推断未执行，也不自动重新执行。

`OperationSnapshot.finalization` 分别保存 `business` 与可选 `outcome`，两者使用带 `status` 的 `OperationOutcome`，成功空值也显式保留 `value`。关闭意图存在而 `outcome` 省略只说明结果尚未确认。`business_effect_count` 标记同一有序副作用账本的业务前缀；进入关闭后旧业务控制不能追加副作用，关闭使用相同可信调用身份及剩余账本预算。已确认的导出、业务结果、前缀边界和关闭结果不可被后继记录替换。终态以业务错误优先；业务成功但关闭失败则返回关闭错误，两个原结果仍可独立查询；两阶段成功时终态返回业务值。两个阶段各自使用 `max_value_bytes`，加上终态投影及序列化元数据后仍受日志记录、写入队列及 FFI 响应的既有总量限制，宿主须据此配置，不宣称单值上限等于总记录上限。

运行时关闭先停止新操作、能力注册与发现，并取消业务控制，保留已登记关闭阶段的精确能力入场；原生和排队调用使用同一阶段门，维护扫描不能按普通业务状态误取消关闭请求。显式注销及权限撤销仍对全部阶段立即生效。全部真实操作排空后才关闭代理并释放能力所有者。低层未登记调用不获得关闭阶段特权；关闭不强杀已进入原生代码的工作。该声明和查询字段经原有 `register_pool` 及操作查询进入版本一 JSON FFI 与生成 SDK 契约，兼容性描述使用新契约摘要，不能混用旧摘要的 SDK。

## 原生宿主资源所有权

Rust 宿主可以通过 `ModuleResourceOwner::new(Arc<T>)` 把真实文件租约或依赖保留对象传入 `EmbeddedPoolManager::create_pool_with_owner`、`EmbeddedRuntime::register_pool_with_owner`。包装保留真实强引用；路径、版本字符串、弱引用及清理回执不能替代它。同一不可变代次的多个执行域可以克隆同一包装，公共池与专用池采用相同所有权规则。宿主负责保证资源对象与 `ModuleDefinition` 的代次一致；核心不能从不透明原生对象验证或推断这种对应关系。

池在注册成功后立即保留所有者，包括尚未创建 VM 的状态。等待分配、实际初始化、普通调用、固定会话、空闲实例及失败后的退役都通过同一注册保持所有权。关闭只停止入场；仅在注册关闭且所有真实 VM 和预留释放后，注册才放弃其引用。真实模块先销毁，再释放容量和注册保护；失败清理保留原实例并重试，不提前解除宿主保护。多个池或宿主另有强引用时，需要等待最后实际持有者释放。已关闭且排空的池、历史操作、会话元数据及退役回执不会单独继续固定此资源。

此接口是轻量保留机制，不是清理回调。资源析构必须不阻塞、不触发 panic、不重入运行时；主动关闭、线程等待、进程停止及可失败清理应先进入对应显式生命周期协议。最后引用可能在注册失败的调用线程、空池关闭线程或退役线程释放；不能依赖固定线程。释放不持有注册自身的身份锁，但不承诺所有上层调用栈都没有元数据锁。资源对象也不得强引用拥有它的运行时或池，避免形成引用环。

原生所有者不授予任何 Lua 能力，不写入 JSON、C ABI、生成 Schema 或历史日志，不能通过序列化恢复文件锁。现有不带所有者的入口保持可用，此时宿主自行承担资源生命周期。绕过池的 `LuaEngine::create_embedded_module` 同样要求调用方独立保留外部资源。跨语言 SDK 必须在其真实运行时及原生模块完全关闭前保留自己管理的文件／库／线程；本 Rust 接口不等于跨语言析构回调注册。独立于 VM 存活的外部服务、Hook 或其他宿主使用者仍须单独持有相同代次的真实引用，不能因为池排空就假定所有外部资源结束。

本地测试使用独立文件句柄的真实共享／排他锁、真实 Lua 终结屏障、初始化失败、待分配租约及公开固定会话，核对提前关闭不会释放保护、实际退役后保留历史句柄不再阻挡回收。这些是核心原生接口证据；Vulcan 生产执行链传入其不可变存储固定句柄仍需在正式核心依赖接入阶段验收，不能据此宣称宿主更新事务或 SDK 资源接入已经完成。

## 跨模块物理容量组

低层 Rust 接口新增 VmCapacityConfig、VmCapacitySnapshot 和 ModulePoolPlacement。
PoolGovernor 与 EmbeddedPoolManager 的 register_capacity / capacity / unregister_capacity
显式管理独立容量身份；create_pool_with_placement 使用带标签的 Independent 或 Capacity 归属。
旧 create_pool、create_pool_with_capabilities、create_pool_with_owner 继续明确选择独立归属，
不会自动将同插件的模块合并。底层治理器只认可信宿主提供的精确标识，不自行推断插件、用途或租户。

容量配置仅包含公共／专用归属、最小常驻预留、最大常驻数及物理执行数，使用同一校验器处理
原 PluginPoolConfig 对应物理字段。零最小值合法，公共容量要求零最小值；最大常驻与执行必须为正，
且不超父级。模块成员必须明确引用既有容量、归属类别一致、局部最小预留为零，并且局部上限不超
容量上限。冲突直接拒绝，不复制预留、不静默裁剪或回退。容量注册表与模块注册表各自受原父级
max_registered_pools 限制，成员映射最多与模块注册表同大；尚未引入单独的配置边界值。

原治理器元数据锁同时完成父级、容量级、模块级常驻分配及实际执行许可检查。父级承诺量对每个
独立模块计算实际常驻与局部预留的较大者，对每个独立容量计算全部成员实际常驻与容量预留的
较大者；同一容量只计算一次。请求成员可消费所属容量未用预留，不能消费其他容量的保证。
容量即使尚无成员，或临时调用之间暂时没有模块，也保留原保证；不通过保持一个虚假 VM 来占位。

每个模块仍有自己的不可变定义、代次、安全分区、Lua 状态及真实资源所有者。成员存在时容量
不可移除；成员只有在实际 VM 销毁后才能注销，运行中回调、创建中和退役中槽位继续计费。
空容量的保证由所有者显式注销后归还。父级关闭阻止新容量和新模块发布，物理关闭仍依据实际 VM、
退役线程及原关闭协议；容量元数据本身不创建工作线程或 Lua 实例。关闭后的容量查询可以保留
策略证据，不能将其未用预留数误读为尚有实际 VM。

真实低层测试已经证明两代模块分别预热、计数状态隔离、专用预留不被公共工作借用、模块更替
不重复预留、原生回调阻塞时共同执行上限仍有效，以及另一容量继续执行。预留表示可兑现额度，
不代表已自动初始化同等数量 VM；分组最小值也不承诺每个模块各自保留最低空闲数。

本节属于新增低层物理能力。正式 EmbeddedRuntime 尚未提供容量组登记／归属接口，现有正式池仍
走独立归属。因此插件级聚合、调度队列／清理期活动额度、公平性、跨容量缓存驱逐、自动预热、
FFI 生成契约、三个 SDK 和宿主用途策略仍须在后续阶段接入。不得绕过正式调度器直接创建低层池，
再把该用量宣称为正式插件聚合已覆盖；此新增能力目前也未在跨语言功能描述中宣称可用。

## 正式普通调用运行时

`EmbeddedRuntime` 拥有独立能力注册表、操作注册表、实际池管理器、固定数量执行线程及一个独立监督线程。执行线程数取唯一配置 `max_running_calls`，另有既有池退役线程；提交请求不会创建新线程。监督器独立处理排队取消、原始截止时间、清理结果及空闲维护，即使所有执行线程等待 SDK 回调，控制查询和排队取消仍能推进。

运行时命名空间来自操作系统随机源，随机源失败直接拒绝构造，不回退到时间戳或进程号。直接依赖精确版本 `getrandom = 0.3.4`，现有锁文件已包含该版本；本次锁文件仅增加根包对它的依赖边。接口依据为[固定版本官方随机填充接口](https://docs.rs/getrandom/0.3.4/getrandom/fn.fill.html)。池及操作身份在该命名空间下递增，关闭及遗忘后不复用。

`register_pool` 要求其插件已经显式注册预算，再冻结模块、域策略、注册快照、实时权限及执行修订，返回不透明池 ID。`submit` 只接受该精确 ID、已声明导出、结构化参数及可信上下文；输入 Schema 与单值大小在初始化前校验。队列入场同时检查父级和插件级数量、完整请求序列化字节、执行域排队上限及操作记录容量。字节包含池身份、导出、参数和上下文，不只计算参数。操作记录满时拒绝新任务，不驱逐未完成或未显式遗忘的结果。

调度按可信插件身份轮转，同一插件增加执行域不会增加轮转权重。普通域内保留先进先出分发；固定会话按会话身份分别保持先进先出，同域其他会话在并发预算允许时可以继续推进。串行域及插件聚合执行槽均保留到实际清理与终态发布，不因执行线程已返回就允许超过声明的并发。

调度准备只摘取空闲所有权或原子预留容量，不构造 VM、不执行源码、不调用宿主。固定工作线程随后初始化并调用导出；同一租借跨 `Result` 失败与调用栈 panic 捕获保持所有权。放弃尚未分配 VM 的准备只释放预留，明确返回没有实例；初始化失败后必须保留实际 VM 退役回执，不能因为返回了错误就发布假完成。

容量紧张时，轮到冷插件会触发最多一个空闲实例的压力退役，并保留专用最小值，避免热插件持续重用自己的空闲 VM 使冷插件饥饿。槽位仅在真实退役后重新可用，期间请求继续消费原始截止时间。此机制不承诺中断阻塞的原生终结器，也不把调度公平解释为任意插件执行时长下的固定延迟保证。

执行结果进入监督器后保留有界输出，释放不再使用的参数与上下文。可保留的租借在业务证据封存、磁盘确认及终态发布后回到精确会话或调度缓存。带独立关闭声明的保留型实例将后续关闭责任转给生命周期操作，因此业务终态不表示 VM 已销毁；单次调用及直接退役路径仍等待其精确关闭／退役回执。Lua 可以直接调用其他受管 API，因此外层副作用保守报告未知；已注册宿主能力的逐项提交证据仍完整保留，不能将整次执行成功自动解释为统一事务提交。

操作查询从唯一阶段状态和实时宿主证据投影：初始化或执行中存在未完成能力记录时显示等待宿主；清理及终态不被该投影覆盖。等待超时仅返回当前状态。内部工作线程失败被显式记录，关闭查询返回错误，不能把线程异常退出当作成功关闭。

`close_pool` 关闭精确代次，排队旧请求失败，不转投新代次；已入场普通调用仍保留原始代码及上下文，固定会话则进入显式关闭与协作取消。其他执行域可继续工作。`forget_pool` 仅允许关闭、无排队和执行任务、无保留会话且实际常驻归零的池；保留池元数据也受注册上限约束。该接口是更新事务的基础，不替代完整插件包安装、迁移、持久回滚及恢复流程。升级编排仍须在请求关闭前检查业务会话能否结束，不能将底层关闭能力解释为默认允许强制升级。

`request_close` 关闭调度及能力发布、关闭旧快照的分发门，并请求取消所有活跃操作；控制调用不运行原生闭包析构器。监督器在操作收敛后负责闭包实际释放和能力排空。`poll_closed` 同时要求执行线程、监督线程及实际池退役线程完成并等待退出。仍在执行的 SDK 请求必须提交实际完成确认，不能靠超时释放语言对象或卸载动态库。

Rust 宿主可通过 `EmbeddedRuntime::with_journal_worker` 显式启用阶段检查点；它与默认内存构造入口共用调度实现，不探测或降级。宿主负责共享日志及写入者的独立生命周期，运行时关闭只排空自身执行和回执，不能替代该外部写入者的关闭／等待。开始执行的检查点由固定执行线程等待确认，清理及终态由独立监督器提交和轮询；磁盘等待不占调度锁。执行期检查点失败后，原始操作、结果和实际 VM 退役责任仍进入监督器，不沿线程错误返回路径丢失。

`persistence_failure(operation_id)` 查询当前保留的精确检查点故障，包括原操作、候选阶段、存储错误及等待／已请求／重试中状态；没有故障不证明尚在途的写入已成功。一个操作最多保留一项当前故障，其数量受原操作入场预算约束。故障存在时暂停新分发并拒绝新调用／会话打开，但已执行工作的完成、取消、查询、VM 退役和显式恢复继续可用。容量恢复不会自动重试；`retry_checkpoint(operation_id)` 只请求一次原检查点重试，重复请求在已经请求或重试中时返回假，不运行 Lua、不换身份、不替换业务结果。请求关闭后仍可修复持久化，真实关闭必须等待原操作完成；未知提交仍遵循日志自身停写及显式对账边界，不能靠该入口绕过。

终态处理区分准备、磁盘确认和公开发布。在调度锁内检查已请求的会话关闭及真实清理回执，冻结一次业务结果和关闭判定；锁外提交／观测磁盘写入；确认后在同一调度锁内发布公开终态并释放活动记账。因此客户端看到终态后可立即遗忘，不能遇到“终态已发布但调度记账仍占有”的间隙。准备前已请求的会话关闭纳入此操作清理；准备后才请求的关闭归后续会话生命周期，不改写已冻结结果，但会话及整个运行时仍必须等待实际 VM 析构。存储失败不会把成功业务值改为另一次执行，也不会提前公开候选值。

自动预热及完整升级事务仍待实现。可信宿主历史对账见下文，外部事实查询由宿主负责。语言 SDK 事件泵已在独立仓库接入同一队列协议。嵌套异步调用图属于后续扩展，当前不声明支持；原生同步回调递归向同一运行时提交任务会在队列入场前被拒绝，不能靠增加线程绕过依赖环。

## 可复用实例的独立关闭与结果发现

`Reusable` 池声明关闭时，每个新实例在初始化前额外预留一个全局及插件操作槽；继续复用同一实例不重复预留。若不能取得该预留，本次业务操作在执行源码前显式失败，不冒充仅物理容量不足的排队等待，也不驱逐其他池来掩盖保留额度不足。未初始化取消或失败初始化释放未使用槽。预留只覆盖内存操作容量，不预留磁盘历史记录或字节；持久容量失败仍保留原 VM 及候选，要求显式恢复。

业务错误、截止、使用额度耗尽、空闲过期、容量压力驱逐，以及池／插件／运行时关闭，使实例永久退出业务复用。先确认原业务结果，再转换预留并调度独立关闭，最后确认关闭结果和实际退役。池及插件代次关闭排空已执行普通调用，不额外取消其业务控制；运行时显式关闭仍按原协议取消业务。关闭继续受池、插件、全局执行许可及实时权限约束。每个声明关闭的实例只保留最近实际分发的一份可信调用上下文，排队但未分发的请求不能替换它。关闭预算在唯一签发时开始，不能复用原业务截止时间。

`list_operations(pool_id, after_operation_id, limit)` 按实际入场发布顺序分页发现保留操作，包括独立关闭。提前预留的 ID 可能小于稍后业务 ID，因此分页使用独立发布次序，不按 ID 排序。返回身份数组、末游标及本次观测的 `has_more`；空页保持输入游标，后续发布可继续发现。游标必须仍被保留，遗忘后返回明确未找到并要求重新枚举。池过滤对照原始上下文，因此池已遗忘后仍可查询其保留结果。记录及分页工作空间均受唯一 `max_operations` 上限约束，不建立第二份无界生命周期记录；分页只枚举当前内存记录，不替代持久历史，也不保证多页之间的整体快照。

关闭操作的原模块上下文带有 `finalization_instance_id`，即实际原 VM 身份；业务基线为成功空值，实际关闭结果位于 `finalization.outcome`。关闭失败不改写已发布业务结果。查询或遗忘关闭记录不会重放函数，也不会重新获得关闭执行权。自动预热、宿主生产路由和发布验收仍独立待完成。

## 正式固定会话

独立关闭操作的模块上下文增加可选 `finalization_instance_id`，在初始化前预留时从原租借身份冻结。普通业务、开启操作和早期历史记录省略此字段；缺失不能反推出历史上没有关闭行为。该字段不构成新执行授权，后继持久记录不能替换原上下文。

声明关闭回调的会话在开启前额外预留一个操作保留槽，同时计入全局与插件的 `max_operations`。因此开启至少需要开启操作与关闭预留两个空位；预留只分配内部身份、校验并保存原池、实例和会话权威，不发布操作、不启动关闭预算。普通入场不能消费该槽，`plugin.reserved_operations` 单独报告预留数量，与 `retained_operations` 相加才是占用的操作额度。开启拒绝、未初始化取消及失败初始化释放未使用预留，不运行关闭函数。

正常调用继续返回原业务结果。显式关闭、业务错误／截止／使用额度耗尽、池代次关闭、插件关闭或运行时关闭后，先等待原会话的全部业务操作及拒绝记录终态，再把原 VM 转给独立关闭操作；转换预留不要求重新取得普通队列容量。关闭仍受池、插件和实际全局执行许可约束。执行器在这些会话排空前不能提前退出。原业务结果及其持久记录不可被后续关闭改写。

`session.finalization_operation` 在调度关闭后给出独立操作身份，关闭后仍保留，可通过原操作查询／持久恢复入口观测。该操作的模块上下文使用原池代次、原会话和声明的关闭导出；调用上下文来自最后实际分发的业务调用，尚未调用的会话使用初始化时的空上下文，未分发请求不能替换它。每个会话至多保留一份已按请求字节上限检查的上下文，关闭后释放。关闭操作的 `finalization.business` 是显式成功空值基线、`business_effect_count` 为零，实际结果位于 `finalization.outcome`；两个阶段成功时操作终态值仍为空值。关闭错误会出现在该操作及会话首次错误字段，原业务错误不被覆盖。关闭身份只保证独立且绝不复用，内部预留使其序号可能早于稍后公开的业务操作，不应用字符串排序推断执行先后。

关闭意图和结果继续经过相同持久确认，任何确认丢失都仅显式重试存储，不重新执行关闭函数。业务关闭只执行一次；可重试的实际资源退役仍独立。只有关闭操作终态且原 VM 真实释放后会话才为 `Closed`。遗忘会话不删除关闭操作，遗忘关闭操作也不重新获得关闭执行权。

`EmbeddedRuntime::open_session` 只接受声明 `Session` 的精确池。创建前原子预留真实常驻容量；容量不足立即拒绝，不挤出其他固定会话。准备阶段不执行源码。返回不透明 `session_id` 与初始化操作句柄，后者仍使用固定工作线程、原始截止、有界队列及统一日志。初始化尚未成功发布时，会话业务提交返回忙碌。普通 `submit` 不接受会话池，必须使用 `submit_session`。

会话绑定池、模块代次、安全分区和唯一实际 VM。`submit_session` 从已注册会话取得池身份，逐调用业务参数不能改变归属。初始化和后续调用的能力身份均包含该会话 ID；源码初始化不伪造一个业务导出调用。初始化操作的成功值为包含 `session_id` 的对象。

同会话一次仅有一个操作拥有 VM，直到执行、宿主确认、清理和操作证据封存完成。成功后精确租借回到此会话，不进入普通空闲池。不同会话可以在父级及域预算内独立推进；声明串行的整个域仍只运行一个调用。会话空闲保留常驻名额，不保留执行许可，不参与普通空闲 TTL 或压力驱逐；宿主根据会话业务空闲策略显式关闭。达到成功使用上限会退役会话，不透明重建状态。

`close_session` 永久拒绝新调用并请求取消实际所有者，控制线程不运行 Lua 析构。队列中的会话调用失败；已分发宿主请求必须真实确认后才能释放调用及 VM。初始化失败、实际执行失败或取消同样退役整个固定会话；只取消尚未分发的一次业务调用不会损坏健康会话。尚未分发的创建取消时，仅释放准备预留，绝不执行初始化源码，也不在预留未释放时发布操作终态。

`session` 返回 `Opening`、`Ready`、`Running`、`Closing` 或 `Closed`，保留精确池、当前操作、排队数量和首个失败。关闭要求所有接纳操作已发布终态且实际 VM 回执完成；队列摘除不等于操作完成。真实终结器阻塞时仍为 `Closing`，资源继续计费。初始化或调用成功结果的发布与会话重新可用在同一调度锁内协调，后续提交不会因成功已可见而丢失租借。

`max_sessions` 是唯一显式会话元数据上限，包含关闭但尚未遗忘的会话。`forget_session` 仅允许完全关闭，遗忘不删除原操作日志，也不复用身份。旧池的会话记录仍在时，池不得遗忘。关闭整个运行时也排空全部会话，最终线程退出与动态库释放仍以 `poll_closed` 的完整证据为准。

## 插件跨域聚合预算

`register_plugin` 接收可信插件 ID 与显式 `EmbeddedPluginConfig`，必须先于该插件所有建池操作。未注册直接报错，不从首个池猜测总预算，不生成默认插件。插件策略不可变；声明的池最大值超过插件最大值会在建池时拒绝，不自动裁剪。父级 `max_registered_plugins` 限制保留插件注册数量，包含正在关闭或尚未遗忘的注册。

插件预算覆盖全部安全分区、执行类别及新旧包代次：常驻 VM、已分发执行与清理、排队请求数量及精确字节、保留池、固定会话和操作记录。上下文字节同样计入；队列取消、截止或分发在同一元数据事务中释放父级、插件级与域计数。操作结果仍计入插件保留上限，即使原池已经遗忘或调用方丢弃句柄；只有显式 `forget_operation` 成功才释放它。

所有正式运行时新分配都在唯一调度元数据锁下决定，固定会话准备也使用此入口。插件预算检查后，池继续原子检查父级和域预算；中间不会先占一层许可再阻塞等待另一层。退役线程可并发减少实际占用，不能增加占用，因此检查期间下降的快照最多保守拒绝，不会造成超额分配。初始化、Lua 执行、回调和实际 VM 析构均不在此锁下运行。

常驻承诺按每个域的实际占用与仍有效专用最小值的较大者合计。请求域可以消费自身保证；其他域的未使用保证不出借。同一插件增加更多专用域不能超过插件预算，所有插件合计仍受原父治理器约束。关闭旧池不立即释放承诺；实际 VM 销毁且精确池注册释放后，其贡献才归零，不要求宿主先丢弃旧池元数据。

插件额度已满时仍可复用同一域的健康空闲 VM；需要新实例时，只能在本插件内选择可驱逐空闲状态。不能为了插件局部耗尽而驱逐无关插件缓存。目标域自身已经达到常驻上限时，驱逐其他域不能帮助它，调度器保留排队等待。父级容量耗尽仍使用既有跨插件压力回收，但保留专用保证和固定会话。

`plugin` 返回有效策略、真实 VM 状态、常驻承诺、活跃操作、排队字节及各类保留计数。`close_plugin` 原子停止该插件全部新池和调用入场，关闭其所有精确池；已运行普通调用继续持有原代次，固定会话按会话关闭协议收敛，无关插件继续执行。关闭尝试覆盖所有所属池，即使其中一个报告错误，最终仍返回实际错误。`forget_plugin` 只有在入场已关闭且全部池、会话、操作记录显式移除后成功。

当前能力调用仍受运行时父级及各能力描述的在途、字节和并发限制；本节不宣称新增了逐插件子进程、原生内存或全部宿主能力的聚合硬配额。后续预热和升级候选也必须通过上述正式分配入口，不得把内部低层池暴露成绕过聚合预算的生产路径。

## 逐实例清理回执

`ModuleRetirement` 只持有一个精确实例的元数据，不持有 VM、引擎或动态库。普通复用期间保持 `Live`；实际退役依次可观察 `Queued`、`Running`、失败后的 `Retrying` 及最终 `Completed`。记录有界尝试计数和最近错误码，不复制原生错误原文或业务值。等待超时返回当前快照，不取消清理、不释放容量、不生成假完成。

退役线程在受管资源关闭成功后，先销毁整个常驻对象，包括真实 Lua 状态、容量令牌及注册保护对象，再发布 `Completed`。池中其他实例仍运行时也能查询这个实例的完成；不能用整个池归零代替逐操作清理证据。回执完成也不代替整个退役工作线程退出，卸载仍需管理器关闭完成检查。

`ModuleLease::finish` 消费独占租借，明确返回已归还复用池或仍需退役的回执。会话、单次、失败或已关闭池的实例不会误报普通复用。显式 `close` 后仍能取回相同回执。`acquire_tracked` 和 `open_session_tracked` 在初始化错误中返回已分配 VM 的回执；分配前拒绝则没有回执。兼容的低层 `acquire`、`open_session` 仍仅返回原始错误，高级运行时应使用带清理证据的入口。

导出函数根必须先于主 Lua 所有者释放，使导出闭包拥有的对象可以在 Lua 仍存活的最后一次垃圾回收中终结。已用真实 `__gc` 与文件屏障验证：终结器阻塞时回执仍在运行，常驻容量不能释放，管理器不能报告关闭完成。

**边界：回执证明 VM 所有权销毁，不证明任意业务终结器成功。** 当前锁定的 mlua 0.12.0 在主 `Lua::drop` 执行垃圾回收，并在 `RawLua::drop` 调用原生 `lua_close`。仍被全局变量引用的终结器可能直到原生关闭才运行；此时调用 Rust 托管 IO 会产生已销毁 Lua 的诊断，并可能被 Lua 终结错误机制吸收。已验证该诊断不等价于 Rust 退役线程退出。不得依赖该阶段的 `__gc` 完成宿主写入、提交或业务清理确认；这些行为必须进入显式操作、能力及后续生命周期协议。相关实现以锁定依赖源码为准，参考 [mlua 状态所有权源码](https://docs.rs/mlua/0.12.0/src/mlua/state.rs.html) 与 [原生状态销毁源码](https://docs.rs/mlua/0.12.0/src/mlua/state/raw.rs.html)。依赖升级时重跑终结器行为测试，不能根据 panic 钩子输出推断进程或线程生命周期。

正式普通调用监督器已接入回执及初始化、调用的 Rust 栈展开捕获。清理长期阻塞、进程崩溃及持久化恢复仍不能仅靠普通 `Result` 和内存回执解决；这些属于后续恢复协议及工作进程后端的验收范围。

## 操作记录基础

`OperationRegistry` 保存当前运行时的有界内存记录。ID 为不透明字符串；显式遗忘后不复用序号。容量已满时拒绝新工作，不能驱逐未完成操作。只有终态记录允许显式遗忘；未知或过期记录不表示未执行过。

`OperationHandle` 只提供查询、等待及取消请求，不能完成操作。`OperationOwner` 是唯一执行权威；必须经过清理阶段才能发布终态。非法提前完成返回错误并保留所有者，允许按正确生命周期继续处理。

执行阶段、取消请求和副作用结果分别记录。调用方等待超时只返回当前状态，不自动取消工作；接收到取消请求也不提前释放 VM 或把执行标为终态。宿主确认写入已经提交时，即使执行随后取消或结果超大，提交证据仍保留。

默认注册表是内存日志。Rust 宿主可显式通过 `OperationRegistry::with_journal` 选择下述直接阶段检查点，或通过 `OperationRegistry::with_journal_worker`／`EmbeddedRuntime::with_journal_worker` 接入队列后端；高级运行时默认构造入口仍为内存模式。涉及逐次宿主副作用的跨重启去重、对账仍需完整执行链和宿主事务服务接入；当前不能承诺高级运行时的跨重启查询或恰好执行一次。

## 持久操作记录基础组件

`OperationJournal` 提供独立的同步磁盘记录组件，已经通过队列接入 Rust 显式选择的操作注册表、调度器、逐次宿主分发意图及处理器已返回的副作用证据确认。FFI 可通过 `runtime_initialize.persistence` 显式选择持久模式，线协议和关闭归属见 [FFI 契约](embedded-ffi.md#持久模式与历史访问)。默认高级运行时仍使用内存模式，不自动创建数据库。宿主不得在调度器或注册表全局锁内直接调用同步磁盘组件。

`OperationRegistry::with_journal` 使用宿主提供的新运行时命名空间和共享日志。入场仍只分配有界内存记录，不在注册表锁内写盘，也不宣称排队回执已持久化。所有者推进初始化、执行、宿主等待或清理阶段时，先保存下一阶段的精确快照，再发布内存阶段；调用方仅能在阶段推进成功后继续执行。初次检查点容量不足时，实时阶段保持排队，尚未开始业务。失败后可在明确修复容量时重试同一尚未执行的阶段，不新建或重绑操作身份。已有磁盘身份不能被同命名空间的新注册表覆盖；历史读取始终走日志接口。

所有者完成操作时先封存全部已结束宿主证据，并保留原始有界结果。终态检查点确认前，公开快照仍为清理中；落盘失败后不能再次提交其他结果覆盖原完成尝试。`pending_completion` 仅供唯一执行所有者查看未发布的原始候选，不能当作公开终态；`retry_completion` 仅重新保存这份原结果，保留当前取消意愿，不重放插件。未知提交仍由日志阻止重试。只遗忘内存终态不删除磁盘记录，历史保留及清理由宿主通过明确日志接口管理。

操作的持久回执门禁与公开状态锁独立；磁盘阻塞不占有快照及取消锁。默认内存模式沿用同一阶段转换规则，但不为阶段推进复制整个副作用账本。直接日志低层入口仍需宿主正确驱动所有者，且明确拒绝宿主能力分发并返回不支持；要执行持久宿主能力，必须显式选择下述队列后端，不静默创建线程或降低持久要求。

`OperationJournalWorker` 是共享同一日志的可选有界写入组件，每个对象只创建一个固定存储线程。`submit` 只校验、计量不可变请求并尝试入队，不访问磁盘；返回的 `JournalWriteReceipt` 表示写入尝试已入场，不表示记录已持久化。回执明确区分排队、写入和完成；完成必须检查精确修订号或错误，不能只根据阶段推断成功。日志记录限制、冲突或实际磁盘容量错误通过原回执返回。单个存储拒绝不终止队列；日志本身的不确定提交门禁仍然生效。

`OperationJournalWorkerConfig` 要求显式的正数量与合计请求编码字节上限。计费包含原始运行时、可选比较交换修订号及完整操作快照，覆盖排队、执行和调用方仍保留的已完成回执；回执克隆共享同一费用。只有最后真实所有者释放，才归还配额。这个字节预算约束 JSON 表示，不是堆内存或磁盘占用硬上限；它与日志单条记录／数据库上限各有归属。`wait` 的预算只约束观测等待，到期返回当前状态；丢弃回执也不能取消已接纳的写入。没有后台重试或按错误猜测新修订号。

写入线程不在队列或回执锁内执行 SQLite 事务；磁盘等待时仍可入队、查询、请求关闭。`request_close` 永久拒绝新工作并排空已接纳队列；`poll_closed` 只在真实线程结束且全部回执释放后确认关闭，故意保留的回执会阻止完全排空。线程故障保留基础设施诊断并结束未完成回执；已发布成功修订不会被后续监督故障覆盖。关闭仅证明资源排空，必须另外检查线程状态及各个回执的错误。析构只请求关闭，不能当作允许卸载动态库的证明；宿主必须在卸载之前显式完成关闭及回执释放。

`OperationJournalWorker::recover_worker` 显式重建已失败且实际退出的受监督线程，健康运行时返回假。用户永久关闭意图与基础设施故障分开保存；已经调用写入者 `request_close` 时明确拒绝，恢复与关闭并发也不能覆盖该意图。等待句柄与队列元数据按同一顺序保护，实际线程未退出时返回忙碌；活动及排队尝试必须已由监督器处理，才创建新线程。新旧线程不重叠；原日志、中心、配置、已完成回执及其计费均保留。仍保留的旧回执可以继续使新入场达到容量上限，恢复不能清空计数。重建本身不访问数据库、不提交旧队列，也不执行插件或回调。线程创建失败继续保留原故障及预算，允许稍后显式重试创建。

数据库恢复、写入线程恢复和原操作检查点重试是三个独立动作。线程重建不证明数据库健康；宿主先按故障类型修复基础设施，再对原检查点显式请求重试，由原候选和修订对账已提交但确认丢失的内容。正常查询不自动触发这三个动作。原运行时正在关闭但尚未要求写入者永久关闭时，可以恢复失败线程以排空原操作。元数据锁中毒、回执观察不可证明或线程在监督器之外异常退出时，不能据错误猜测空队列或清除所有权；保持显式故障和实际资源归属，不允许提前卸载库。监督外等待失败在句柄已消费后仍保留，重复调用不能绕过拒绝。

`OperationRegistry::with_journal_worker` 为 Rust 所有者显式接入共享写入队列，`EmbeddedRuntime::with_journal_worker` 使用同一所有者链驱动调度器；宿主负责共享写入者的关闭与等待。原有 `with_journal` 仍是直接同步阶段入口，不会静默转成队列，也不会把非阻塞轮询悄悄转成磁盘等待。默认高级运行时、FFI 和 SDK 仍使用内存模式。

队列后端的宿主分发在处理器开始前持久化精确副作用身份、注册身份和接口版本；队列传输同时保存已绑定的 SDK 请求身份，不从业务参数补造身份。账本在发布给共享控制对象之前绑定精确操作，通过弱引用共享同一个变更门禁和修订权威，不创建所有权循环。阶段与意图均在取得门禁后捕获，旧意图不能越过阶段写入。数据库中的 `Running`／`Unknown` 表示已保存的保守执行许可，不证明处理器已经开始；实时账本在实际分发前仍是 `Prepared`。

原生回调仅在固定执行线程等待意图确认，随后重新检查原始截止时间、权限及注册分发门，才进入处理器。队列提取只尝试提交或观测原回执，写入待完成时返回空批次且请求继续排队；不在代理锁或注册分发门内等待磁盘。JSON 编码先验证可交付预算，待持久确认且实际分发后才进入返回批次。等待期间取消或注销可以阻止分发；随后保存清理及终态时记录真实的未执行结果，不能把磁盘许可反向投影成已经运行的实时处理器。

意图候选跨容量拒绝、取消和显式恢复保持不变。普通回调或队列轮询不重试已知失败，已取消请求留下的正常在途回执可被后续请求排空；恢复确认本身不分发原处理器。Lua 即使捕获开始意图的存储错误并返回业务值，原失败意图仍由操作所有者保留，调度器拒绝提前发布终态，显式恢复只继续原检查点。

处理器返回后，先保存可信副作用状态并校验输出预算，再以同一阶段门禁和修订权威捕获独立确认检查点。原生路径将有界原始返回值及真实注册许可保留在原执行栈中；队列路径将两者移交给代理的原请求记录，保持 `Completing`。确认得到存储回执之后才释放许可、标记真实处理器完成并将原结果交给 Lua。确认快照中的宿主阶段仍可为 `Running`，表示结果已返回但入场所有权尚待释放；后续清理／终态保存真实 `Completed`。确认使用当时当前操作阶段，不能用分发时的旧阶段覆盖已经开始的清理。

队列 `complete` 成功表示精确原结果已被接纳，不保证磁盘确认或请求已进入 `Completed`；重复完成返回 `AlreadyCompleted`，不能替换原值或副作用状态。调用不等待磁盘。监督器、请求查询／等待及队列维护只推进原确认，已知失败保持等待显式恢复。即使等待方退出，代理仍保留真实确认所有者及许可，直到确认、释放和过期处理完成；关闭不能用等待超时代替这些步骤。

共享检查点失败可在原生回调尚未返回 Lua 或 SDK 请求仍完成中时通过 `persistence_failure` 查询，`retry_checkpoint` 在原候选上记录单次恢复意愿。故障观测与入场暂停串行化；过期的健康观测或忙碌门禁不能清除已知暂停。查询共享门禁忙碌时明确返回 `Busy`，调用方稍后重查，不将其解释成故障消失。取消及注销不能清除已经返回的提交证据；关闭中的运行时仍允许恢复，原许可和真实工作线程收敛前不能确认完全关闭。

此确认持久化的是精确宿主副作用记录及当前操作快照，不把所有宿主业务返回值另建一份无界磁盘缓存；在途原返回值按既有输出预算保留在真实所有者中。原始代次上下文随操作保留，日志重新打开可读取历史；外部事务对账及完整跨语言恢复仍待接入，未知提交仍受日志停写约束，不能据当前实现承诺跨重启自动恢复执行或安全重放。

队列所有者的 `poll_advance` 首次捕获并提交精确阶段候选，之后只观测同一次写入。待完成时返回假，公开阶段保持上次确认值；另一阶段不能越过或替换该候选。若已有阻塞阶段推进持有变更门禁，轮询直接返回待完成，不排队等待该门禁。磁盘拒绝及队列入场失败均保留原候选和错误，即使容量随后恢复，普通轮询也不再次写入。`retry_advance` 或对同一阶段显式调用阻塞 `advance` 才可重试原候选；在原阶段得到确认之前不能跳到清理或其他阶段。调用方必须在真实阶段确认后才执行对应业务，重试检查点本身不会调用插件。

`prepare_completion` 在清理完成后封存可信证据及有界原始结果，不提交 I/O。`poll_completion` 只开始或观测该终态写入；失败后保留原值、错误及清理状态，不能再传另一业务结果覆盖。`retry_completion_nonblocking` 显式重试原始候选，既有 `retry_completion` 则在执行线程阻塞等待。队列后端的每个已准备快照保持不可变，后来发生的取消继续由实时查询投影，不能把它改写进已排队字节或反推为磁盘已保存；直接同步入口只在新的显式尝试前刷新取消。回执观测本身若不可信，则保留实际回执所有权并拒绝重试，而非推断旧事务已结束。非阻塞接口在直接同步日志上明确报错；内存模式可使用相同的准备／轮询接口并立即完成发布。

本地队列组件测试以真实存储门禁验证控制响应和实际所有权，以仅测试可配置的故障位置验证写入前失败及发布后 panic；操作集成测试进一步覆盖真实磁盘与队列容量拒绝、修复后仍不自动重试、并发阻塞阶段推进时轮询仍响应，以及原始结果在终态落盘之前不可见。真实 Lua 调度测试覆盖执行前存储失败阻止源码初始化、磁盘阻塞时监督器仍移除取消队列、实际 SQLite 页耗尽后只重试存储且业务追加次数保持一、终态后的立即遗忘，以及终态准备后关闭会话仍保留成功结果并等待真实 VM 析构。分发意图测试覆盖处理器内读取真实预写记录、队列请求身份、磁盘阻塞期间空交付、取消及独立注销后的拒绝、已取消前驱不饿死后续请求，以及真实 Lua 捕获拒绝后的显式恢复。完成确认测试覆盖原生返回值及许可跨故障保留、正常和关闭期间恢复、SDK 控制在实际阻塞磁盘释放前返回、拒绝替代原值、容量修复不自动重试，以及孤立请求确认不倒退清理阶段。故障注入不是实际设备故障；这些证据尚不覆盖跨重启对账、FFI 或 SDK 的持久配置。

宿主显式提供受控本地目录下的绝对数据库路径及 `OperationJournalConfig`。插件无权决定存储路径。组件使用与 Vulcan 宿主对齐的 `rusqlite 0.40.2`／`libsqlite3-sys 0.38.2` 和捆绑 SQLite；不要求用户预装 SQLite。一个日志对象至多拥有一个独占连接，重复打开及时报忙；显式恢复先释放故障连接，再打开原始文件。目录的访问权限、磁盘可靠性及禁止外部替换文件由宿主负责；此组件不将不可信目录、网络文件系统或摘要视为安全隔离边界。

存储格式独立于包版本：固定应用标记、第四版结构及 4096 字节页。第四版在明确入场上下文、原始可信调用身份之外增加独立最终对账字段；该字段必须存在，尚未对账时显式为空。未发布开发阶段的第一至三版文件明确拒绝并保留原字节，不从当前插件补造身份，也不自动清空或升级。打开已有文件前先读取 SQLite 固定文件头，未知身份或版本不会交给可写 SQLite 连接；随后由 SQLite 恢复热回滚日志，再检查精确结构、完整性及每条记录。首次创建中断留下的空文件或损坏头不会自动清空重建，应由宿主保留现场并显式处理。原始运行时与操作身份按字面存储，不能解析、重绑或据缺失记录推断“从未执行”。

记录含原始运行时、正修订号、完整 `OperationSnapshot` 及独立可空对账证明。完整 JSON 字节计入单条上限，行长度由 SQLite 原生限制约束，身份／修订号与存储索引交叉核对，SHA-256 用于发现数据损坏而非认证。显式 JSON 空值与缺失结果在序列化往返中保持不同。插入禁止覆盖；替换和遗忘要求精确修订号，竞态只有一个成功者。原非终态、未知或未完成副作用在没有最终宿主证明时阻止遗忘；没有自动容量淘汰。

阻塞方法 `OperationJournal::reconcile` 接受精确原运行时、操作、前驱修订及 `OperationReconciliation`，返回唯一持久后继。可信宿主先核实原执行及全部外部所有者已停止，再授权对账者并查询实际外部结果；API 不认证名称、不查询业务系统，也不向 Lua 暴露。最终证明与原快照独立保存；每条副作用按原身份和顺序覆盖，保留已知结果并校验聚合，全部证据共用单记录上限。原非终态只能记录已停止而无结果，不能制造终态或返回值。相同前驱和完整相同证明的重试确认同一后继；不同证明冲突。最终证明不能被普通 `replace` 或运行时检查点擦除，已解决历史可显式按后继修订删除。完整字段与 FFI／SDK 约束见 [持久模式与历史访问](embedded-ffi.md#持久模式与历史访问)。

`get` 读取精确历史；`next` 按二进制身份键序每次枚举一条，方便重启时无需猜测 ID 即可恢复检查。枚举期间并发编辑不构成跨调用快照，宿主应在启动业务前进行一致的恢复扫描。恢复得到的运行中记录仍为历史上的运行中记录，不能作为当前仍在执行的证明；没有执行重放或实时句柄复活。

写事务使用 SQLite 回滚日志、`synchronous=EXTRA` 及可用平台的完整同步。独占连接可能保留回滚文件，因此将 `journal_size_limit` 设为零以收缩非活动日志；这不限制活动事务的临时空间。主数据库按配置字节向下取整至完整页，另有记录数和单条编码上限；数据库上限不包含回滚日志、缓存及文件系统开销，也不是宿主进程堆内存硬限制。磁盘提交或回滚无法证明时，同一对象停止读写，关闭并显式重新打开、读取原记录后才能对账；绝不自行重新发送变更。SQLite 已自动回滚的容量错误按真实事务状态处理，不把二次回滚失败误报为不确定提交。

Rust 宿主可对仍被运行时和写入者持有的同一日志调用阻塞的 `recover_storage`。它仅在保留不确定故障时关闭原连接，按原路径及上限打开既有数据库，并以启动时同一读取器重新校验全部记录。文件缺失绝不创建空库，打开、独占锁或校验失败继续保留故障及读写门禁；修复基础设施后可再次显式恢复。健康日志返回假且不关闭连接。此方法不持有运行时元数据锁，也不自动重试任何已失败操作；宿主不得在调度器、注册表全局锁或回调执行等待环内调用它。

存储恢复成功后，原运行时仍保留自己的故障、不可变候选、业务结果和实际回调许可。宿主对原操作调用 `retry_checkpoint`，固定写入者在同一事务中对照原运行时、操作、预期后继修订及完整编码内容：磁盘已经是精确候选时，仅确认原修订；仍为原前驱或原插入尚不存在时，才写入原候选；不同内容、丢失替换前驱或更晚修订均明确冲突。空值和缺失结果不相同。底层公开 `insert` 和 `replace` 保留严格重复／修订冲突语义；仅运行时内部检查点使用精确候选确认。该流程不重跑处理器，也不把其他运行时历史接管为活动操作。

存储恢复覆盖日志已返回不确定事务错误但原执行所有者仍存活的场景；受监督写入线程已退出时，另用上述显式写入者恢复。回执观察锁已中毒、元数据不完整或原执行栈已随进程退出丢失时，不能据此复活所有者或宣称自动恢复。真实 Lua 测试分别使 SQLite 实际提交和实际回滚后丢失确认，并覆盖写入线程在事务前及提交后、发布确认前实际 panic；原生与队列回调在关闭期间保留原许可，显式恢复后排空，实际业务只执行一次。这些仅测试故障注入不等于设备断电验收。FFI／SDK 已接入显式持久配置、存储及写入线程恢复和历史接口；这些入口不替代实际外部事务对账服务。

底层依据为 [SQLite 文件格式](https://sqlite.org/fileformat2.html)、[同步与日志设置](https://sqlite.org/pragma.html#pragma_synchronous) 及 [自动回滚状态](https://sqlite.org/c3ref/get_autocommit.html)。升级存储依赖或磁盘格式时必须回读对应源码及官方契约，重新验证跨平台恢复，不能仅变更文档版本。

本地测试实际创建数据库并验证重新打开、未知格式原字节保留、逻辑与页容量、修订竞态、损坏拒绝、历史枚举、提交确认不确定状态，以及两个无析构退出的子进程场景。子进程分别在刷新未提交写入后退出和成功提交后退出；父进程重新打开验证真实热日志恢复及已确认数据保留。这些证据不等于电源中断、硬件故障或完整跨进程恢复验收。宿主外部事务去重、插件不可变更新恢复、各 SDK 历史接口仍需后续接入与验收。

关联。明确未绑定的低层调用不从 Lua 上下文补造该字段。旧历史记录省略该可选字段表示原先
没有记录关联，不能按当前请求补全；已保存的关联同其他调用方字段一样不可重新指向。

`OperationSnapshot.context` 是必需的明确来源：`kind=unbound` 仅表示低层 `OperationRegistry::admit` 没有模块绑定；正式调度操作始终为 `kind=module`。模块上下文在原子入场及控制对象发布前从精确 `ModulePool` 构造，包含原池 ID、完整可信调用方、注册时能力快照修订及请求导出；仅会话开启操作的导出为显式空值，并已绑定新会话 ID。普通调用的初始化及导出共用同一操作上下文。业务参数、当前插件注册、首个回调及后来池替换都不能改写这些字段；上下文是历史证据，不是重新执行的授权。

模块上下文与逐回调记录合计计入 `max_effect_bytes_per_operation`，在入场前为上下文预留份额，后续回调使用剩余预算；固定的 `unbound` 标记按固定协议元数据处理。未通过上下文校验或预算检查的请求不会绑定控制对象、发布操作或执行 Lua。实时回调必须与入场调用方完全一致，日志写入及恢复再次检查上下文和副作用调用方的一致性；已有持久记录的上下文不能由替换检查点改写。入场本身仍只发布有界内存记录，磁盘确认遵循上述执行前阶段及终态检查点；不能据此宣称排队接纳响应已等待持久确认。

`OperationRegistry::admit` 将有界 `EffectLedger` 原子绑定到原始 `CallControl`。一个控制对象只能属于一个注册操作；已经执行过未跟踪能力的低层控制对象不能事后注册成看似完整的日志。注册与首次未跟踪调用通过同一状态锁确定归属，不能因竞态漏记之前的调用。显式低层执行仍可使用未注册控制对象，但 `host_effects` 返回未配置日志，而非“确定没有副作用”。

每次宿主能力调用先预留 `HostEffectRecord`，再允许实际分发。记录包含原始 `caller`（运行时、插件、包代次、执行修订、安全分区、操作及可选会话和工作区）、不复用的副作用 ID、精确能力注册、名称、版本、可选 SDK 请求 ID、处理器阶段与副作用证据，不记录业务参数和凭证。调用身份直接复制自已验证的宿主绑定；日志写入和恢复时交叉核对原运行时及操作，身份缺失或矛盾不能以摘要正确为由接纳。运行时配置的 `max_effect_records_per_operation` 和 `max_effect_bytes_per_operation` 分别限制单操作累计记录数及记录序列化元数据总量，完整调用身份也计入；已完成记录同样计入。预算耗尽在新处理器执行前拒绝，不能丢弃旧提交证据腾出空间。

元数据为生命周期的最大拼写预留空间，附加请求身份时再次计入原预算。请求身份一旦进入可查询日志，即使随后注册关闭、队列未发布，也必须消耗序号而不再复用。记录按实际入场序号返回，不按不透明字符串的字典顺序排序。

记录阶段依次为准备、运行、完成。开始分发后，在宿主确认前副作用为未知；收到实际确认后立即记录提交、回滚或其他证据。确认不等于释放：处理器及其入场许可真实释放后才标记完成。操作所有者提前发布终态会得到忙碌错误；最终封存与新副作用入场使用同一日志锁，终态之后不能再出现未记录的新能力调用。

`OperationSnapshot.host_effects` 始终保留逐调用证据。`effects` 是概览，不能被解释为多个宿主调用自动组成一个事务：存在未知或未完成调用时概览为未知；已确认提交不会被另一个调用或外层所有者报告的回滚抹掉；同时发生的提交、回滚和未知状态仍可在各记录中分别查询。结果超限、Lua 报错、输出 Schema 不合法或取消只改变执行结果，不改写已确认提交。

注册操作初始化沿用原始操作身份和预算，初始化中的宿主调用也归入该日志；明确未注册的低层模块初始化才使用实例生命周期身份。正式普通调用运行时协调 VM 执行、请求清理、退役和操作所有者；低层手动组合调用仍由宿主承担该责任，不能只因副作用记录已完成就推断整个 VM 已销毁。默认模式只保留内存证据，显式队列日志后端按上述检查点落盘；它不替代宿主外部事务的持久去重与对账服务。没有能力调用的正式操作同样保存入场模块上下文，其空副作用列表不需要用于推断模块归属。

## 实例能力注册与可靠宿主请求

`CapabilityRegistry` 属于一个明确的运行时实例。批量注册先完成全部声明与 Schema 校验，再原子发布；名称冲突或容量不足不会留下半个批次。注册身份与快照修订为不透明字符串，名称重新注册后获得新身份。旧快照只解析原先捕获的精确注册，不会转向同名新实现。注册保留数量包含已注销但尚未显式遗忘的条目。

`CapabilityDescriptor` 显式声明语义版本、输入输出 Schema、原生或队列传输、授权集合、调用或会话作用域、并发、时长、值大小及副作用和去重契约。仅注册能力不会自动授权。`CapabilityCaller` 独立携带运行时、插件、包代次、执行修订、安全分区、操作及可选会话和工作区身份，不能由业务参数覆盖。宿主构造该身份；嵌入式 Lua、FFI 队列及各 SDK 已接通，实际 Vulcan 插件入口仍待迁移，不能把本地绑定当成完整产品链路已经上线。

快照冻结实现身份，权限集合保持实时可撤销。原生回调使用 `authorize` 在副作用前重新检查；队列处理器通过请求状态读取取消、截止或撤权原因。原始操作截止时间与能力时长取较早者，不因等待、投递或查询重新计时。会话能力要求可信会话身份。当前禁止原生回调同步重入同运行时，包括再次提交队列请求，防止阻塞自身事件泵。

原生回调直接接收结构化输入。panic 转换为固定错误；副作用状态仍独立记录。请求失败、取消、输出 Schema 不合法或返回值过大，都不能把宿主确认的提交改成未执行。当前原生传输不提供队列请求身份，因此拒绝声明 `HostRequest` 去重；队列请求提供稳定身份，但持久去重仍由宿主实现，不等于核心已提供跨重启恰好执行一次。

Rust 原生回调可通过 `CapabilityBudget::is_finalization()` 读取核心登记的关闭阶段标记。
仅已登记的操作关闭控制返回真；业务参数、导出名称及低层独立控制均不能自行选择该阶段。
该标记只提供来源证据，不授予宿主权限、不替代 `authorize()`、实时撤权或截止检查。
宿主若允许旧实例在更新排空期间清理，仍须校验自己签发的精确代次授权及保留包内容。
此方法为 Rust 原生适配接口，不增加 JSON、C ABI 或队列 SDK 字段。

`HostRequestBroker` 使用运行时独立控制通道，原生与队列能力共同消耗父级实际在途预算。队列同时约束保留记录数，以及包含调用身份的请求序列化字节与最大应用输出预留；固定协议错误元数据按有界记录数独立计算。计数使用流式 JSON 计数器，包含 UTF-8 与 JSON 转义，不先分配第二份完整 JSON。此预算不是 Rust、Lua 或语言 SDK 堆内存的硬限制。

队列状态为排队、已分发、完成中、已完成。取请求与精确注册门共同决定开始分发，每个请求最多交付给一个消费者。批量取回时，后续内部错误不会吞掉已经成功取出的请求，失败请求仍留待后续调用显式报告。SDK 只能完成已经分发的精确身份；提前完成报忙碌，重复完成报 `AlreadyCompleted`。近期完成墓碑有数量上限，过期身份报 `NotFound`；二者都不能解释为外部副作用未发生。

排队期间取消、撤权、超时或注销时，不启动宿主实现，结果为未开始。已分发后取消只记录意愿，继续保留调用许可，直到实际处理器提交完成确认。确认迟到且已提交外部写入时，返回失败原因并保留已提交证据。丢弃等待句柄也不能释放仍在执行的 SDK 回调；完成确认后才能清除没有等待者的记录。关闭代理停止新投递并请求取消，不能强杀语言回调。

注销关闭精确注册门并主动排空尚未分发的请求，不依赖 SDK 继续取请求；已分发处理器继续持有原实现。注册状态只有在调用结束且回调闭包真实析构结束后才报告排空。把闭包从槽位取走不能作为 SDK 释放引用或卸载动态库的依据。显式遗忘只允许已排空注册。

`CapabilityOutcome` 通过唯一 `to_json` 入口产生显式信封：成功含 `ok=true`、`value` 和 `effects`；失败含 `ok=false`、`error` 和 `effects`。成功空值仍保留 `value`，失败不伪造应用值。FFI 与 SDK 的生成契约引用同一核心结构并执行真实消费验证，不能各自选择另一种 Rust 枚举序列化形状；字段变化必须同步生成及验证消费端。

## Lua 实例绑定

`ModuleCapabilities` 冻结注册快照和宿主执行配置修订，同时持有实时权限。直接创建使用 `create_embedded_module_with_capabilities`，池使用 `create_pool_with_capabilities`；池内每个新实例继承同一个绑定。绑定仅能在模块初始化前安装一次，不能替换已运行实例的权威。更新注册表后必须新建绑定及对应池，不能热改旧 VM 的函数目的地。

嵌入式模块在运行源码前安装 `vulcan.capabilities.list/has/call`。`vulcan.host` 使用同一代理表；旧进程全局宿主工具回调不再是嵌入式模块的回退路径。既有全局模型和技能管理入口在该 VM 中移除，相关业务需通过显式注册能力访问。没有绑定时发现为空、调用拒绝。此变更仅适用于新嵌入式模块，旧技能与 System 租约兼容入口仍维持既有行为；整个产品尚未迁移到新入口。

调用方运行时来自能力快照；插件、包代次、安全分区和工作区来自冻结模块声明；执行修订来自绑定；操作与可选会话身份由宿主逐次传入 `ModuleInvocation`。注册操作的初始化沿用原始操作身份，未注册低层初始化使用实例生命周期身份。调用上下文存于 Lua 不可写的应用数据，在执行保护对象释放时移除；业务参数中的同名字段没有权威。复用实例不会继承上一调用的操作或会话身份。

能力传输严格按捕获描述选择。原生能力直接执行；队列能力在当前 VM 执行线程等待，仍占用真实 VM 与执行许可；控制线程可独立取请求、查询、取消及确认结果。能力调用前复制应用数据，不跨宿主等待持有 Lua 应用数据借用。当前没有为每个能力调用额外创建线程。

已注册操作的回调提交证据可独立于 Lua 返回结果查询，正式调度、会话、统一关闭、FFI 控制通道及 SDK 事件泵已接入该内存证据。持久去重对账及实际宿主暴露链仍待完成。真实 Lua 与 SDK 测试已覆盖宿主提交后取消、报错和输出 Schema 失败的内存证据保留，不能将其解释为跨进程崩溃恢复或持久对账验收。

## 验证范围

定向测试位于 `src/runtime/embedded/tests.rs`、其操作记录子模块、`src/runtime/embedded/capabilities/tests/`、`src/runtime/engine/tests/embedded.rs` 及 `embedded/pools.rs`，FFI 测试位于 `src/ffi_embedded/`。测试使用真实 LuaJIT，验证模块导出、包身份、实际池复用与预热、固定会话、并行宿主等待、关闭、容量隔离、Schema、取消和操作记录状态。能力测试另验证真实并发取回与完成、闭包析构屏障、实例隔离、在途取消、撤权、注销、输入输出字节及迟到提交。SDK 原生消费及安装包验证记录在各 SDK 仓库与实施方案中。当前证据限本地开发环境；五平台、长期稳定性、升级故障注入及完整发布验收仍是正式发行前条件。
