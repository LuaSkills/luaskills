# LuaSkills v0.9.1 upgrade guide

This guide describes the v0.9.1 development target. Registry and GitHub installation instructions apply after the release is published. Build from the current checkout with Rust **1.99.1**, the minimum version declared in `Cargo.toml` and selected by `rust-toolchain.toml`.

## Migrate skill packages

| Before | v0.9.1 |
| --- | --- |
| Package-level and entry-level `help` fields | Move operating instructions to `skills/<guide>/SKILL.md` and declare the guide in `registration.prompt_skills`. Old fields are accepted during manifest parsing and ignored at runtime. |
| Each entry published directly | Omit `registration` for direct discovery or choose `registration.mode: explicit`. With a bundled guide, a supporting host can opt individual entries into implicit dispatch. |
| Large tool lists exposed up front | Choose `registration.mode: implicit` and bundle at least one guide. The host publishes the guide and resolves actions through its dispatcher. |
| Adapters derive public names independently | Use `RuntimeEntryDescriptor::public_tool_name()` to obtain the runtime's underscore form. Core rejects public-name collisions when building its registry. |

The package and each guide supply nonempty `title` and `description` for `registration.default_locale`. Keep input constraints in each entry's `input_schema` or `input_schema_file`. Package the `skills/` directory with the manifest. See the [authoring example](../development/skill-development.md#25-package-registration-and-prompt-skills).

## Migrate hosts and SDK consumers

- Rust hosts discover visible entries through `list_entries_for_authority` and registration declarations through `list_skill_registrations`. Use the exact selected entry descriptor with `call_implicit_skill`. It verifies the active package instance and validates arguments against its compiled schema before invoking Lua.
- The existing C/JSON FFI help exports remain present. On valid requests they return an error saying package help was removed. FFI and SDK hosts can continue direct entry discovery and calling through `list_entries` and `call_skill`. Registration discovery and implicit dispatch described above are Rust APIs in this checkout. Host model tools, guide names, policy and rendering are host integration choices.
- Treat physical guide paths as host metadata. Model-facing discovery can publish the guide name and localized description, then return the body and resource directory from the host's dedicated skill-loading tool.
- The `luaskills-packages` distribution still carries a help index for Lua modules and runtime packages. Its files are part of the [packaged-runtime layout](../integration/ffi-overview.md) and are independent of skill-package help.
- Language SDKs follow the `0.9` core series and resolve the latest published core patch with the matching embedded contract digest. See the [SDK version rules](../sdk/index.md#versions).

## Runtime and lifecycle changes

- A malformed or failing package is logged and skipped during root loading. Its higher-priority identity still shadows lower layers. Failed install/update operations roll back, and failed enable operations preserve the active state.
- Dependency installation uses staging and atomic publication. Cleanup respects in-use dependency roots and shared state owned by an effective package in another layer.
- Execution deadlines cover Lua and supported blocking host operations, including process I/O, Python/Node invocation, and managed environment builds and lock waits. An expired evaluation remains failed even if Lua catches an intermediate error. Uninterruptible native calls retain lease ownership until they return. See [execution deadlines](../../contracts/system-lease-execution.md).
- Provider FFI boundaries contain panics and guard deeply nested values. Rust 1.99.1 replaces deprecated atomic updates with the equivalent standard-library API.
